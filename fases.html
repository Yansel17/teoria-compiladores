Sección 3

Las fases del proceso de compilación

Para que las fases no queden en abstracto, todas se aplican aquí a la misma línea de código. Es el ejemplo clásico del Dragon Book, adaptado:

posicion = inicial + velocidad * 60

  1. Análisis léxico (scanner, lexer)

    Lee el programa carácter por carácter y agrupa los caracteres en unidades con significado llamadas tokens: identificadores, números, palabras clave, operadores y signos de puntuación. Descarta espacios, saltos de línea y comentarios. Cada token tiene un tipo y, cuando hace falta, un valor (el lexema). Los identificadores se registran en la tabla de símbolos.

    Entrada posicion = inicial + velocidad * 60
    Salida ⟨id,1⟩ ⟨=⟩ ⟨id,2⟩ ⟨+⟩ ⟨id,3⟩ ⟨*⟩ ⟨num,60⟩
    Errores típicos carácter no permitido (@), número mal formado (12.3.4), cadena sin cerrar
    Teoría expresiones regulares y autómatas finitos (Tipo 3)

  2. Análisis sintáctico (parser)

    Recibe la secuencia de tokens y comprueba que respete la gramática del lenguaje. Mientras lo hace, construye un árbol sintáctico que refleja la estructura jerárquica del programa: qué operación se hace primero, qué pertenece a qué bloque. En el ejemplo, el árbol muestra que la multiplicación se evalúa antes que la suma, porque * queda más abajo que +.

    Entrada secuencia de tokens
    Salida árbol sintáctico (AST)
    Errores típicos paréntesis sin cerrar, falta de ;, operador sin operando (a + * b)
    Teoría gramáticas libres de contexto y autómatas con pila (Tipo 2)

  3. Análisis semántico

    Comprueba que el programa, además de estar bien escrito, tenga sentido según las reglas del lenguaje que la gramática no puede expresar: que cada variable esté declarada antes de usarse, que los tipos de una operación sean compatibles, que una función se llame con el número correcto de argumentos. Su principal tarea es la verificación de tipos; cuando el lenguaje lo permite, inserta conversiones implícitas. En el ejemplo, si posicion, inicial y velocidad son de tipo float, la constante entera 60 debe convertirse a float antes de multiplicar.

    Entrada árbol sintáctico + tabla de símbolos
    Salida árbol anotado: * ( velocidad, inttofloat(60) )
    Errores típicos variable no declarada, tipos incompatibles, asignación a una constante, break fuera de un bucle
    Teoría gramáticas de atributos, sistemas de tipos

  4. Generación de código intermedio

    Traduce el árbol anotado a una representación intermedia: un "lenguaje máquina abstracto", fácil de producir y fácil de traducir después a cualquier procesador real. La forma más común es el código de tres direcciones, donde cada instrucción tiene como máximo un operador y tres operandos (dos fuentes y un destino), usando variables temporales.

    t1 = inttofloat(60)
t2 = velocidad * t1
t3 = inicial + t2
posicion = t3
    Entrada árbol anotado
    Salida código intermedio (tres direcciones, bytecode, CIL, LLVM IR…)
    Teoría traducción dirigida por la sintaxis

  5. Optimización de código

    Mejora el código intermedio para que el programa final sea más rápido, más pequeño o consuma menos energía, sin cambiar lo que calcula. Algunas técnicas: plegado de constantes (calcular 2 * 30 en tiempo de compilación), eliminación de código muerto, eliminación de subexpresiones comunes, propagación de copias y optimizaciones de bucles. En el ejemplo, la conversión de 60 puede hacerse de una vez y la variable temporal t3 sobra:

    t1 = velocidad * 60.0
posicion = inicial + t1
    Entrada código intermedio
    Salida código intermedio equivalente, pero mejor
    Nota es la fase opcional: gcc -O0 casi no optimiza; -O2 y -O3 aplican cientos de pasadas

  6. Generación de código (código objeto o final)

    Traduce el código intermedio al lenguaje de la máquina destino: ensamblador o código máquina para x86-64, ARM, RISC-V… Aquí se toman las decisiones que dependen del hardware: qué instrucción usar para cada operación (selección de instrucciones), qué valores guardar en los registros del procesador, que son pocos y rápidos (asignación de registros), y en qué orden emitir las instrucciones (planificación).

    MOVF   velocidad, R2
MULF   #60.0, R2
MOVF   inicial, R1
ADDF   R2, R1
MOVF   R1, posicion
    Entrada código intermedio optimizado
    Salida código ensamblador / código objeto
    Después el ensamblador y el enlazador producen el ejecutable

Qué se transforma en cada fase

Una forma útil de recordar las fases es fijarse en cómo cambia la representación del mismo programa: texto, lista de tokens, árbol, árbol con tipos, instrucciones simples, instrucciones simples mejores, instrucciones de la máquina. Cada fase conoce solo la representación anterior y la siguiente, y por eso se pueden diseñar, probar y reemplazar por separado.
