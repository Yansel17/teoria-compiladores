Sección 5

Principales compiladores empleados en la actualidad

La teoría de las secciones anteriores está detrás de herramientas que millones de programadores ejecutan cada día. Estas son las más usadas, con el lenguaje que traducen, la representación intermedia que emplean y el dato que las hace relevantes.

Compiladores de propósito general

GCC

GNU Compiler Collection · C, C++, Fortran, Ada, Go, D, Objective-C

Desde
1987 (Richard Stallman, proyecto GNU)
IR
GENERIC → GIMPLE (SSA) → RTL
Licencia
GPL (software libre)

Es el compilador del sistema en casi todas las distribuciones de Linux y el que compila el núcleo Linux. Su diseño con tres representaciones intermedias (una por nivel de abstracción) es un ejemplo de libro del modelo front-end / back-end.

gcc.gnu.org

Clang / LLVM

C, C++, Objective-C (Clang) · infraestructura para muchos otros lenguajes (LLVM)

Desde
LLVM 2003 (Chris Lattner, Univ. de Illinois); Clang 2007
IR
LLVM IR (SSA, tipada)
Licencia
Apache 2.0 con excepciones LLVM

Clang es el front-end; LLVM aporta los optimizadores y los back-ends. Es el compilador por defecto en macOS, iOS, Android NDK y FreeBSD, y su IR la reutilizan Rust, Swift, Zig, Julia y muchos más: la idea "N + M" hecha realidad.

llvm.org · clang.llvm.org

MSVC

Microsoft Visual C++ · C, C++

Desde
1993 (Visual C++ 1.0)
IR
propia; no usa LLVM
Licencia
propietaria, gratuita con Visual Studio Community

El compilador cl.exe incluido en Visual Studio. Es la referencia para desarrollo nativo en Windows (Windows API, DirectX, drivers) y el que compila el propio Windows y Office.

learn.microsoft.com/cpp

Compiladores a código intermedio con máquina virtual

javac + HotSpot

Java (OpenJDK)

Desde
1995 (Sun Microsystems); OpenJDK 2006
IR
bytecode de la JVM (archivos .class)
Licencia
GPLv2 con excepción Classpath

javac hace el front-end y genera bytecode; la máquina virtual HotSpot lo interpreta y lo compila con sus JIT (C1 y C2) a código nativo mientras el programa corre. Kotlin, Scala y Groovy producen el mismo bytecode y comparten la JVM.

openjdk.org

Roslyn + RyuJIT

C#, Visual Basic (.NET)

Desde
C# 2002; Roslyn de código abierto desde 2014
IR
CIL (Common Intermediate Language) + metadatos
Licencia
MIT

Roslyn, la ".NET Compiler Platform", es el compilador de C# escrito en C# (autoalojado). Además de compilar expone su árbol sintáctico y su análisis semántico como API, lo que permite construir analizadores y refactorizaciones en Visual Studio. El CLR termina el trabajo con el JIT RyuJIT, o antes de tiempo con Native AOT.

github.com/dotnet/roslyn

kotlinc

Kotlin

Desde
2016 (Kotlin 1.0, JetBrains)
IR
bytecode JVM; también LLVM IR (Kotlin/Native) y JavaScript (Kotlin/JS)
Licencia
Apache 2.0

Lenguaje oficial para Android desde 2019. Un solo front-end con tres back-ends distintos: otro ejemplo de que separar análisis y síntesis permite apuntar a varias plataformas.

kotlinlang.org

Compiladores de lenguajes modernos de sistemas

rustc

Rust

Desde
2015 (Rust 1.0, Mozilla; hoy Rust Foundation)
IR
HIR → MIR → LLVM IR (back-ends alternativos: Cranelift, GCC)
Licencia
MIT / Apache 2.0

Su fase de análisis semántico es famosa: el borrow checker verifica en tiempo de compilación que el programa no tenga errores de memoria ni condiciones de carrera. Rust se usa en Linux, Android, Windows y Firefox.

rust-lang.org

Go (gc)

Go

Desde
2012 (Go 1.0, Google)
IR
propia, en forma SSA
Licencia
BSD

Go tiene su propio back-end en lugar de LLVM, una decisión tomada para que la compilación fuera muy rápida. Compilar para otro sistema operativo o arquitectura es tan simple como cambiar dos variables de entorno.

go.dev

swiftc

Swift

Desde
2014 (Apple); código abierto desde 2015
IR
SIL (Swift Intermediate Language) → LLVM IR
Licencia
Apache 2.0

Lenguaje principal para iOS y macOS. Usa una IR propia de alto nivel (SIL) para optimizaciones específicas del lenguaje antes de bajar a LLVM IR: dos niveles de código intermedio en un mismo compilador.

swift.org

Un caso especial: el compilador de TypeScript

tsc traduce TypeScript a JavaScript, es decir, de un lenguaje de alto nivel a otro. A esto se le llama transpilador o compilador fuente-a-fuente. Realiza análisis léxico, sintáctico y, sobre todo, un análisis semántico muy completo (la verificación de tipos es su razón de ser), pero su "código final" es JavaScript legible. Desde 2012 lo desarrolla Microsoft bajo licencia Apache 2.0, y en 2025 anunció una reescritura nativa del compilador en Go para acelerar la compilación de proyectos grandes. typescriptlang.org

¿Cuáles se usan más?

Entre los desarrolladores de C, la encuesta The State of C 2025 de JetBrains registró el siguiente uso de compiladores (la suma supera 100 % porque muchos usan más de uno):

  • GCC
    82 %
  • Clang
    44 %
  • MSVC
    21 %
  • Keil
    11 %
  • clang-cl
    8 %

Fuente: JetBrains, The State of C 2025. Keil es un compilador para sistemas embebidos; clang-cl es Clang con la interfaz de línea de comandos de MSVC.

Fuera del mundo C/C++, el "compilador más usado" depende del ecosistema: javac y la JVM en Java y Android (con Kotlin), Roslyn en .NET, rustc en Rust, y tsc en el desarrollo web, donde buena parte del código JavaScript que se despliega pasa antes por TypeScript.

Línea de tiempo

  • 1952 Grace Hopper desarrolla el sistema A-0 y populariza la palabra "compilador".
  • 1957 FORTRAN (IBM, John Backus): el primer compilador optimizador de uso masivo.
  • 1972 Nace C en Bell Labs (Dennis Ritchie), diseñado para que su compilador fuera portable.
  • 1975 Lex y Yacc: generadores de analizadores léxicos y sintácticos a partir de expresiones regulares y gramáticas.
  • 1986 Primera edición del Dragon Book de Aho, Sethi y Ullman; la segunda, con Monica Lam, es de 2006.
  • 1987 Primera versión de GCC.
  • 1995 Java: compilación a bytecode y ejecución en una máquina virtual.
  • 2002 .NET Framework 1.0 y C#: compilación a CIL y JIT en el CLR.
  • 2003 LLVM 1.0; Clang llega en 2007.
  • 2012 Go 1.0 y TypeScript.
  • 2014 Microsoft libera Roslyn como código abierto; Apple presenta Swift.
  • 2015 Rust 1.0.
  • 2016 Kotlin 1.0.
